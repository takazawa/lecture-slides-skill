# lecture-slides — HTML スライド（→ PDF）

1 枚 = `<section class="slide">`（1280×720）。見た目は共通の CSS、PDF 出力と機械チェックは共通のスクリプトにまとまっている。スライドごとに見た目を作り直さない。

## はじめて使うとき（プロジェクトに 1 回だけ）

1. このスキルの `engine/` を、プロジェクトの直下に `slides/` という名前で写す（`slides/deck.css` `slides/deck.js` `slides/build.mjs` `slides/sheet.mjs` `slides/package.json`）。
2. `slides/` で `npm install` を実行する（puppeteer-core と KaTeX が入る。ブラウザはダウンロードしない）。
3. 必要なもの: **Node.js** と、**Chrome か Microsoft Edge**（Windows は Edge がはじめから入っている）。ブラウザが見つからないときは、環境変数 `CHROME_PATH` にブラウザの場所を入れる。

`slides/` がすでにあれば、この手順は飛ばす。

| ファイル | 役割 |
| --- | --- |
| `slides/deck.css` | 共通のデザイン（主色・役割色・赤ペン・窓の絵・数式・表・グラフ） |
| `slides/deck.js` | 節名・ページ番号・目次・KaTeX の描画 |
| `slides/build.mjs` | PDF 出力と機械チェック 15 種 |
| `slides/sheet.mjs` | ページ画像を 9 枚ずつの一覧にする |
| `<フォルダ>/slides.html` | 1 本のスライド。1 本につき 1 フォルダ |

## 流れ

1. **中身を決める**。誰に、何を伝えるかを確かめる。元の資料（原稿・既存のスライド・論文など）があれば、内容・数値・条件はそこから取り、勝手に足さない・削らない。変えたものは最後に報告する。プロジェクトに `CLAUDE.md` などの決まりがあれば、それに従う。
2. **1 枚ごとに型を選ぶ**。[references/patterns.md](references/patterns.md) の型から選ぶ。1 枚に主役は 1 つ。
3. **書く**。[assets/template.html](assets/template.html) を `<フォルダ>/slides.html` に写して始める。見た目の決まりは [references/design.md](references/design.md)。そのスライドだけの調整は、その HTML の `<style>` に書く。2 本以上で使う部品は `slides/deck.css` に足す。
4. **文章を推敲する**。言い回しの AI っぽさ（決まり文句・不自然な比喩・飾り）を直す。意味・条件・用語・数式は変えない。日本語の推敲スキル（例: yomiyasu）が入っていれば使う。
5. **ビルドして機械チェックを 0 件にする**。
   ```bash
   node slides/build.mjs <フォルダ>/slides.html
   ```
   PDF は `<フォルダ>/<フォルダ名>.pdf` に出る。指摘の意味と直し方は [references/checks.md](references/checks.md)。指摘を消すために中身を足さない。
6. **全ページを目で見る**。ビルドが出すページ画像のフォルダを `node slides/sheet.mjs <そのフォルダ>` で 9 枚ずつの一覧にし、全部見る。機械が拾えないもの（図の意味の取り違え、式の読みにくさ、色の使いすぎ、間の抜けた余白）を見る。
7. **数値と事実を確かめる**。計算し直す。外の数字・事例は出典を確かめ、`<フォルダ>/sources.md` に控える。
8. **別のエージェントに読ませる**（新しく作ったとき、大きく直したとき）。作り方を知らないサブエージェントに PDF を読ませ、分かりにくい所・誤り・抜けを挙げさせて、採否を決めて直す。

## 守ること（要点）

- **1 枚に主役は 1 つ**。画面の絵・グラフ・表・式のどれか。文字だけのページは、用語の定義（`.terms`）か箇条書き 3 つまで。
- **色は 3 層**。地は主色と灰色。式の部品と説明を結ぶときだけ役割色 3 色。注記は赤ペン。それ以外の色は、画面の絵とグラフの中だけ。
- **枠はそろえる**。1 枚の中で横に並ぶ枠は上端と高さ、縦に積む枠は左端と幅を同じにする。強調で枠の大きさを変えない。
- **影・模様・絵文字を PDF に残さない**。PDF で灰色の四角に化けるビューアがある（チェック 15）。
- **語りかけない**。体言止めと短い常体にし、話す内容は口頭に回す。「Point」「まとめ」のような定型の箱を足さない。頼まれていない活動・ルールを足さない。
- **余白**。授業中に書き込む資料なら、ゴール・まとめ・例題の下に書き込む余白を残す。書き込まない資料なら、文字や図を大きくして空きを埋める（中身は水増ししない）。

## デザインを変えるとき

主色は `slides/deck.css` の `:root` の `--shikon`（と、役割色 3 の `--rc`）で変える。新しい種類の部品を足す、色や書体を変えるときは、見た目の AI っぽさを洗い出すスキル（例: unslop）があれば使い、方向をユーザーに確かめてから `deck.css` を直す。直したら既存のスライドをビルドし直して、崩れていないか見る。
